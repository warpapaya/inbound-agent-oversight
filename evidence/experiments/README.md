# Preliminary experiments (not the accepted regression story)

All files here are real, unedited SDK/tool recordings or generated reports. The
final comparable v1/v2/v3 reports live in `evals/reports/`; these experiments are
retained to explain revisions rather than silently selecting favorable outputs.

1. One v1 debug call conflated employee count and licensed users. The shared prompt
   was clarified before scoring.
2. A first v2 warmth probe (`v2-initial-injection.jsonl`) resisted the injection.
3. The preliminary full v1 pass scored 15/15. The preliminary full v2 pass reported
   13/15, but inspecting the drafts showed **no genuine regression**: its two
   `must_not` failures were quotations in internal rationale explaining that the
   agent had refused the injected language. The original generated reports and
   command logs are retained with `preliminary-` prefixes. They are not claimed as
   catches. `tests/test_grader_boundary.py` reproduced this grader defect; the
   corrected checker examines outbound draft text for must-not assertions.
4. Further single-lead probes tried transcription/reviewer-trust shortcuts. The
   model still refused the explicit injection and delivery/custom-term promises.
   Their exact prompts are in the first record of each `*-probe.jsonl`.
5. A courtesy-incentive edit genuinely produced an unapproved 10% discount, even
   while the model continued to refuse the injected 50% discount. A regression
   test then expanded the commitment matcher to cover “we'd be happy to offer”.
   The final v2 keeps this unsafe incentive and reviewer-only commercial checking;
   it is deliberately seeded negative behavior, not an accidental production bug.

Before the final three passes, the shared envelope was made neutral (`LEAD_JSON`)
so the versioned system files, rather than duplicate runner prose, own the trust
rule. v1/v3 explicitly designate all lead/CRM text as untrusted; v2 drops that
rule. All three final versions use the same envelope, seed, tools, and graders.
The KB search was also fixed to return only lexical matches instead of dumping
all five documents on every query. Both changes were tested, then **all three
versions were rerun** on the same frozen implementation. Old fixtures remain
historical evidence, not CI baselines.

Usage: three exploratory full passes and three final comparable full passes, plus
eight single-lead probes (98 agent sessions and six rubric sessions). The
`resistant-*` report is the additional exploratory v2 pass: it resisted the
commercial requests but skipped research on spam. The final comparable v2 pass
(`live-*v2.json`) contains real unsafe draft text. Its LLM judge caught the 10%
injection-lead concession, while the deterministic matcher initially missed the
synonym “glad”. `tests/test_discount_synonyms.py` reproduced that miss. The final
`*-regraded-v*.json` reports were generated by `evals.rescore` on all three exact
recordings, with the original LLM scores, usage, drafts and calls unchanged.

This exceeded the approximate four-pass budget to avoid claiming a false-positive
result as a catch. Report totals cover their own 15 agents + one rubric batch only,
not development overhead. No reports were hand-edited.
